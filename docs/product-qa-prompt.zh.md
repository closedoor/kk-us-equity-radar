# 美股雷达：测试、修复与完善提示词

你正在维护一款中文美股研究网站。使用生产站正在运行的 Git 提交和最新主线作为基准，完成以下五轮工作。你的交付是复现证据、修复、针对性回归、候选版本验收及上线核对。只写建议不算完成。不得把以往通过的测试记为本轮结果。

1. **基线与用户任务。** 记录生产版本、提交、纽约观察日、接口生成时间、覆盖率、是否正在刷新、是否接入授权行情。线上只读；失败记录 HTTP 状态或超时，不把网络失败称为停服。分别模拟首次访问者、手机用户和熟悉模型的研究者：能否在首屏回答「市场是否在跌、依据是哪一天、结构分说明什么」？从摘要打开六项报价、来源、模型权重和前瞻记录，记下不能回答或容易误解的地方。
2. **行情与时间。** 区分报价观察时刻、收盘时段、核对时刻、模型日度输入和浏览器时间。以纽约开盘前、盘中、盘后、周末、节假日、提前收盘、跨日和夏令时为边界；交易日历使用可溯源资料。复现 SPX 与等权 RSP 同跌、仅权重股跌、仅半导体跌、缺少对照、错日、已过期及离线。逐一核对 VIX/VXSMH 的单位、前收、交易时段和来源。缺数时仍应告诉用户已确认的事实，不把缺数解释为平静，不把历史参考当成自动行情。
3. **结构分与证据。** 从十二项原始风险值和权重独立复算覆盖率、基础分、风险组加分和共振项，再与接口核对。特别核查覆盖临界点上下、原始值为零、日期不同步、刚发布新经济数据、财报待审核及手动覆盖。检查前瞻记录的观察日、有效分数与结果成熟度。保留不可评分的真实样本；不补造历史数据，不因最近涨跌直接调权重。若当前缺数，找造成缺数的具体依赖与日期，对照同日发布证据判别是保护生效还是误伤。
4. **修复与回归。** 每个问题写下最小复现、旧结果、预期结果、影响与验证方式。优先修会让读者作出相反判断的问题，再修移动端交互。使用可控时钟和录制样例测试失败路径；不得改系统时间、个人数据、生产缓存或测试断言来制造通过。运行数据、HTTP 和模型测试，以及桌面、320/390/440 像素视口、键盘、20 像素最小字号的浏览器场景。检查首屏、详情锚点、断线重试、恢复及本地人工输入，用 Chromium 与 WebKit 对照；模拟视口不称为 iPhone 实机。
5. **发布与验收。** 审阅差异，剔除无关文件，保留前瞻记录与人工数据。先运行候选版本的完整自动检查，失败时保留失败证据、修根因并重跑受影响检查。按项目既有授权发布。部署后用实际域名核对版本、构建提交、接口字段与真实数据期，重走本次修复的关键任务。最后用中文说明「发现了什么、改了什么、怎么证明、还做不到什么」，附永久提示词、测试结果和网站链接；列明跳过或未完成的项目。
